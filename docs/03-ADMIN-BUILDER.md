# ADMIN BUILDER — current contract

## 1. المبدأ

Admin يدير مكتبة مراجع تفتيش مستقلة بصريًا، دون حاجة إلى كود أو SQL.
لا يوجد مرجع منشور واحد يلغي غيره، ولا دورة Draft → Publish كعقد منتجي حاكم.

## 2. مكتبة المراجع

Admin يستطيع:
- إنشاء أكثر من مرجع SHARED؛
- فتح كل مرجع بصورة مستقلة؛
- تعديل اسمه وبنيته؛
- إضافة/تعديل/تعطيل/حذف العناصر والأوصاف والبنود؛
- معاينة المرجع.

إنشاء مرجع جديد أو تعديله لا يغيّر حالة المراجع الأخرى.

## 3. بنية المرجع

لكل Node: عنوان، وصف، قابل للتفتيش مباشرة، Parent اختياري، ترتيب، Active.
وتحت Node: فروع، أوصاف ديناميكية، وبنود تفتيش.

الحذف الفعلي مسموح في المرجع لأن الزيارات لا تعتمد على المرجع الحي بعد إنشائها؛ كل زيارة تحفظ لقطة داخلية مستقلة.

## 4. الأوصاف

Admin يحدد العنوان، النوع، required، الخيارات عند الحاجة، الترتيب، شرحًا اختياريًا، وactive.

## 5. بنود التفتيش

Admin يحدد العنوان، guidance اختياريًا، الترتيب، وactive.
الحالات القياسية لنتيجة التفتيش ليست جزءًا من تعريف المرجع القابل للتخصيص.

## 6. المراجع الخاصة

المفتش يستطيع إنشاء Reference PRIVATE أو نسخ Reference متاح إلى مكتبته الخاصة.
Admin لا يرى المرجع الخاص الحي ولا يعدله.

إذا اختار المفتش «اقتراح للتعميم»، تصل إلى Admin ReferenceSubmission تحتوي Snapshot ثابتة من المرجع وقت الإرسال.
- Approve → إنشاء Reference SHARED جديدة مستقلة.
- Reject → لا تغيير على المرجع الخاص.
- تعديل المرجع الخاص بعد الإرسال لا يغير Snapshot قيد المراجعة.

## 7. Proposal Inbox

المسار النشط للـProposal الفردي بقي للمؤسسات المضافة ميدانيًا.
Proposal التاريخية من نوع Node/Description/Item لا تُحذف من التاريخ، لكنها ليست مسار التعميم الجديد.

## 8. منع التكرار

قبل إنشاء أو تعميم محتوى مرجعي، يفيد البحث النصي والمراجعة البشرية لتفادي التكرار.
لا يلزم AI لهذا الغرض في V1.

## 9. Governance

Admin واحد مخول يكفي كبداية. لا يوجد Workflow متعدد المستويات ما لم تكشف الممارسة حاجة فعلية إليه.
