# INSPECTOR WORKFLOW — v0.1

## 1. الدخول

المفتش:
1. يسجل الدخول.
2. يرى "زياراتي".
3. يفتح Draft سابقة أو يبدأ زيارة جديدة.

## 2. زيارة جديدة

- اختيار المؤسسة.
- إن لم توجد: + إضافة مؤسسة.
- تاريخ الزيارة.
- إنشاء Draft.

المؤسسة المحلية الجديدة تستخدم فورًا وتولد Proposal تلقائيًا.

## 3. التنقل

يظهر المرجع المنشور كشجرة بسيطة أو Drill-down مناسب للهاتف.

كل Node يمكن أن:
- يحمل مواصفات؛
- يحمل بنودًا؛
- يحمل Children؛
- يكون مجرد حاوية تنظيمية؛
- أو يجمع بين ذلك.

## 4. المواصفات

المفتش يعبئ ما صممه Admin:
- نص؛
- عدد؛
- تاريخ؛
- اختيار... إلخ.

إذا احتاج معلومة غير موجودة:
- + إضافة مواصفة محلية؛
- تستخدم في الزيارة؛
- تولد Proposal.

## 5. بند التفتيش

الحالات:
- غير مفحوص
- غير معني
- مطابق
- ملاحظة
- غير مطابق

مع حقل:
- معاينة/ملاحظة البند.

عند "غير معني" يمكن عرض سبب اختياري.

## 6. إضافة بند

+ إضافة بند

يضاف للزيارة فورًا، ويولد Proposal للمراجعة.
لا ينتظر المفتش قرار Admin.

## 7. إضافة فرع

إذا كان الواقع غير ممثل:
+ إضافة فرع

الفرع محلي للزيارة أولًا، ويمكن تعبئة مواصفاته وبنوده، ثم يذهب Proposal إلى Admin.

## 8. نهاية كل Node قابل للتفتيش

- معاينات إضافية حرة.
- توصيات المجال/العنصر.

## 9. نهاية الزيارة

- معاينات عامة حول المؤسسة/الزيارة.
- توصيات عامة.
- Mark Completed.
- Export JSON.

## 10. Autosave

كل تغيير مهم:
- يظهر "جار الحفظ..."
- ثم "محفوظ ✓"
- وعند الفشل يظهر خطأ واضح مع Retry.

لا يعتمد المستخدم على زر Save وحيد في نهاية صفحة طويلة.

## 11. الاستمرارية

المفتش يستطيع:
- إغلاق الصفحة؛
- الدخول من جهاز آخر؛
- استكمال Draft من الخادم.

## 12. المبدأ الميداني

لا يجوز أن يقول النظام للمفتش: "لا يمكنك تسجيل هذه المعلومة لأن النموذج لم يتوقعها".
كل فجوة واقعية يجب أن يكون لها مسار إضافة محلية دون كسر المرجع المشترك.
