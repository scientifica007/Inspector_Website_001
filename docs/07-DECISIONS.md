## D-014 — لا Implementation ضخم قبل Spike

## D-015 — Quality First / جودة المنتج هي المرجع الأعلى
**قرار:** لا توجد قاعدة تنفيذية أو تاريخية أو توافقية تعلو على إنتاج موقع صحيح مفاهيميًا، متماسكًا، عمليًا، آمنًا، قابلًا للصيانة والتطور، وذا جودة عالية.

**آثار القرار:**
- التنفيذ الحالي ليس Specification نهائية؛ إذا كشف الاستخدام أو الاختبار فرضية تصميمية خاطئة، نصلح التصميم نفسه بدل حماية السلوك القائم لمجرد أنه سبق تنفيذه.
- Backward compatibility قيمة هندسية وليست غاية مستقلة. نحافظ عليها عندما تخدم جودة المنتج، ونرفضها أو نعيد تصميمها عندما تؤدي إلى تشويه النموذج النهائي.
- الاختبارات السابقة دليل تحقق، وليست قيدًا على التطوير. إذا تغير العقد الوظيفي للأفضل، تُراجع الاختبارات أو تُستبدل بما يثبت السلوك الصحيح الجديد.
- حجم الـDiff، سهولة الـRollback، الحفاظ على API/Export قديم، أو تجنب Migration عوامل لإدارة المخاطر فقط؛ لا تستخدم لمنع تصميم أفضل.
- سلامة البيانات، صحة التاريخ، الأمن، الاعتمادية، سهولة الاستخدام، قابلية الوصول، الأداء، وقابلية الصيانة كلها مكونات من جودة المنتج نفسها، وليست استثناءات من هذا المبدأ.
- عند تعارض "الحفاظ على ما بُني" مع "بناء الشيء الصحيح"، يُختار الشيء الصحيح ثم تُعالج آثار الانتقال هندسيًا وبصورة صريحة.


## D-016 — Selective Visit Scope / المرجع مكتبة لا قالب مفروض
**قرار:** الزيارة الجديدة لا تنسخ Master المنشور كاملًا. تُثبَّت على إصدار Master واحد، ثم يبني المفتش نطاقها الفعلي بحرية من المرجع أو من إضافات محلية.

**القواعد:**
- الأصل هو نطاق SELECTIVE فارغ عند إنشاء الزيارة.
- يمكن اختيار Branch كامل أو Specification منفردة أو Checklist Item منفردًا.
- الآباء اللازمة لعنصر عميق تدخل بدور CONTEXT فقط.
- إخراج عنصر من النطاق يتم Soft Exclusion ولا يحذف Snapshot أو البيانات.
- إعادة العنصر تستعيد Snapshot نفسها وقيمها السابقة.
- مصدر الإدراج يُمثَّل بـ LEGACY / MANUAL / GUIDE / ASSIGNMENT / LOCAL.
- scope_locked مستقل عن completion_required؛ الأول يمنع الإخراج من النطاق، والثاني يمنع الإنهاء قبل الحسم.
- الإضافة المحلية من جذر الزيارة أو داخله تستخدم فورًا وتولد Proposal.
- Progress يحسب ACTIVE checklist items فقط.
- Guides وAssignments يبنيان لاحقًا فوق هذه النواة ولا يعيدان فرض Master كاملًا.


## D-017 — Local Authoring Operations / التحرير المحلي يحفظ التاريخ
**قرار:** المحتوى الذي ينشئه المفتش داخل زيارة Draft هو محتوى قابل للتحرير والنقل والنسخ والإخراج، لكن دون كسر Snapshot المرجع أو إعادة كتابة قرارات Governance السابقة.

**القواعد:**
- لا يعدّل المفتش Snapshot قادمًا من Master مباشرة؛ ينسخه كمحتوى LOCAL مستقل ثم يعدل النسخة.
- المحتوى LOCAL يدعم Edit / Duplicate / Copy / Move / Soft Remove / Restore داخل مساحة تحضير الزيارة.
- نسخ فرع ينسخ Subtree النشط المحضّر فقط، ويولد هويات محلية وProposals مستقلة.
- النسخ ينقل التصميم لا نتائج العمل الميداني: قيم الأوصاف فارغة، وحالات البنود تبدأ UNCHECKED، والمعاينات لا تنسخ.
- النقل يحتفظ ببيانات العنصر نفسه لأنه لا ينشئ نسخة جديدة.
- إذا كان Proposal ما يزال PENDING فإن التعديل أو النقل يحدث Payload نفسه.
- إذا سبق حسم Proposal ثم تغير المحتوى LOCAL، ينشأ Proposal جديد ولا يعاد فتح القرار التاريخي.
- إخراج محتوى LOCAL يسحب أي Proposal ما يزال PENDING بحالة WITHDRAWN، ولا يحذف المحتوى ولا بياناته.
- استعادة محتوى سُحب اقتراحه تولد Proposal PENDING جديدًا مع الاحتفاظ بنفس Snapshot وبيانات الزيارة.
- WITHDRAWN تعني «مسحوب من صاحب الاقتراح» وليست REJECTED.
